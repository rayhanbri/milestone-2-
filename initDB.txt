# Better Version

```js
const initDB = async () => {
  try {
    await pool.query(`
      CREATE TABLE IF NOT EXISTS users(
        id SERIAL PRIMARY KEY,
        name VARCHAR(50) NOT NULL,
        email VARCHAR(100) UNIQUE NOT NULL,
        password TEXT NOT NULL,
        is_active BOOLEAN DEFAULT true,
        age INT,
        created_at TIMESTAMP DEFAULT NOW(),
        updated_at TIMESTAMP DEFAULT NOW()
      )
    `);

    console.log("Database connected successfully!");
  } catch (error) {
    console.log(error);
  }
};
```

# Interview Questions

## Basic Questions

### 1. Why use `async/await`?

Because database operations are asynchronous.
---

### 2. What is `SERIAL` in PostgreSQL?

Auto increment integer value.

---

### 3. What is a Primary Key?

A unique identifier for each row.

---

### 4. Difference between `UNIQUE` and `PRIMARY KEY`?

| PRIMARY KEY      | UNIQUE           |
| ---------------- | ---------------- |
| Only one allowed | Multiple allowed |
| Cannot be NULL   | Can contain NULL |

---

### 5. What is `DEFAULT NOW()`?

Automatically inserts current timestamp.

---

# Intermediate Questions

## Why should passwords not use VARCHAR(20)?

Because hashed passwords are much longer.

Use:

```sql
TEXT
```

or

```sql
VARCHAR(255)
```

---

## Why use connection pooling?

Connection pool improves performance by reusing database connections.

---

# Common Mistakes

## ❌ Storing plain passwords

Bad:

```sql
password VARCHAR(20)
```

without hashing.

---

## ❌ Small email length

```sql
VARCHAR(20)
```

Many real emails exceed 20 characters.

---

## ❌ Forgetting NOT NULL

Can create incomplete data.

---

# Important Concept Summary

* `SERIAL` → auto increment
* `PRIMARY KEY` → unique row identifier
* `UNIQUE` → no duplicate values
* `NOT NULL` → required field
* `BOOLEAN` → true/false
* `TIMESTAMP` → date & time
* `DEFAULT NOW()` → automatic current time
* `async/await` → asynchronous database handling
